Methodology

How we write and verify practice questions

Every Azure Mastery question is written against a published exam outline, checked by a fixed set of automated gates, and watched afterwards for drift. This is how that pipeline works.

The outline

Grounded in the published outline

Every question bank is written against the "Skills measured" outline Microsoft publishes for that exam, not against a generic syllabus. Each bank is bound to the specific outline version it was written from — recorded as a hash of that outline page — together with a recorded mapping review confirming the bank's coverage actually maps onto it.

Microsoft revises outlines regularly, and sometimes publishes an upcoming version ahead of its effective date. A weekly automated check compares the live outline against what shipped and flags drift. If Microsoft's new outline is not yet in effect, the check reports it as upcoming rather than treating today's content as already stale.

Explain, don't trick

Written to explain, not to trick

Every question carries a written explanation, not just a marked correct answer. For question formats that call for contrasting the options against each other, that explanation has to clear a minimum length before it can ship — a one-line explanation isn't enough material to cover why the wrong options are wrong as well as why the right one is right.

The app uses several interactive formats beyond plain multiple choice — including drag-and-drop ordering, hotspot, and case studies — but every format exists to test understanding of a skill the outline lists, not to trip a candidate up on ambiguous wording.

Every option

Every option gets a rationale

Where a question carries per-option rationales, every option — not just the correct one — has its own written explanation. That field powers the app's Answer Coach feature: pick a wrong answer and its fallback explanation is built directly from that option's own rationale, so an incorrect choice gets a considered explanation rather than a generic prompt.

The same field is checked for a set of known content-quality defects before it ships: redundant openers that just restate an option as "correct", boilerplate phrases that leak internal review language into candidate-facing text, and rationales that accidentally give away the answer inside a wrong option's own explanation. None of these checks are optional.

Checked always

Checked on every change

Every push and pull request against the question banks runs a fixed pipeline of checks before anything can ship: a schema and integrity validator, the outline-binding and mapping-review check described above, and a set of scanners for specific defect classes — including questions that leak the answer through the wording of the stem itself, and options that just restate the question back at the candidate. None of these checks are advisory; a failing check blocks the change.

Several of the scanners are forward-only: every bank has a frozen baseline defect count, and a change can only lower that count, never raise it. That is deliberate — it stops content quality drifting backwards one unnoticed question at a time.

Watched weekly

Watched weekly against Microsoft Learn

Two automated routines run on a schedule, independent of any content change. Every Monday, a check re-reads the live "Skills measured" page for every exam and compares it, by hash, against what is recorded for the shipped bank — catching outline changes as soon as Microsoft publishes them.

Once a month, a separate routine confirms that every question's "learn more" link still resolves. Microsoft Learn reorganises its documentation continuously, so links that were correct when written do go dead over time; this check finds the ones that have, rather than waiting for a candidate to hit one.

Limits

Frequently asked

FAQs

Are these questions from the real exam?

Every question is an original item — drafted with AI assistance, then reviewed and edited by hand against the published skills outline; nothing is copied, adapted or drawn from a live exam question pool.

How often is content updated?

Whenever Microsoft changes a published skills outline, or whenever one of the automated checks below finds a defect. A weekly watch compares the live outline against what shipped; a separate monthly check confirms every "learn more" link a question points to is still live.

Do you use AI to write questions?

Yes. Draft questions are generated with AI assistance against the exam's published skills outline, then every draft has to pass a set of automated content checks and a recorded human review, with a named reviewer, before it ships.

Do the explanations cover the wrong answers too?

Where a question carries per-option rationales, yes — each option, not just the correct one, has its own written explanation. That field also powers the app's Answer Coach feature, so a wrong answer gets its own explanation rather than a generic "try again".

What happens if a question turns out to be wrong or out of date?

It gets fixed. The checks that catch these defect classes are forward-only: each bank has a frozen baseline count per defect type, and a change can only lower it, so a fixed defect cannot quietly reappear. Broken "learn more" links are found the same way, by a monthly automated sweep, and repaired.
