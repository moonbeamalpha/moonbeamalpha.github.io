The exam

What is the AI-200 exam?

AI-200 is the Microsoft Certified: AI Cloud Developer Associate exam — the credential hiring managers expect when posting "AI Cloud Developer", "AI Platform Engineer", or "Vector Database Developer" roles. AI-200 covers building AI-powered cloud solutions on Azure: compute, vector storage, integration pipelines, security and identity for AI workloads, and operational monitoring.

AI-200 is hands-on and infrastructure-aware. It covers:

  • Develop AI-powered compute solutions — Azure Functions, Container Apps, AKS for AI workloads
  • Develop for vector-enabled storage and data — Azure Cosmos DB vector search, Azure SQL vector capabilities, Azure AI Search vector indexes
  • Implement AI pipelines and integration — Azure Data Factory, Logic Apps, event-driven patterns
  • Implement security and identity for AI — managed identities, Microsoft Entra, Private Link, content filters
  • Monitor and optimise AI solutions — Application Insights, cost controls, performance tuning

Expect scenario questions that combine compute, data, and identity choices.

Common traps

Where AI-200 candidates slip

Five recurring misconceptions that trip up otherwise well-prepared AI-200 candidates, grounded in the current skills outline.

Studying the old five-domain outline

Candidates study an outdated five-domain outline and underweight how much Container Apps and data services now carry.

  • Container Apps and data services carry more combined weight under the current four-domain structure than under the retired one.
  • Check your study source's date before trusting its domain breakdown — Foundry and AI Search are supporting context now, not headings.

Treating every vector store the same way

Candidates apply generic "vector database" knowledge instead of a named service's own configuration surface.

  • Cosmos DB, PostgreSQL, and Managed Redis each tune vector search through a different set of settings entirely.
  • Match the scenario's named service to its own indexing or connection settings before answering.

Service Bus vs Event Grid — reliability vs reaction

Candidates can't tell a guaranteed-delivery requirement from a many-subscribers reaction requirement.

  • Service Bus guarantees ordered delivery to a queue; Event Grid reacts to discrete events across many subscribers.
  • Pick Service Bus for a specific back-end queue, Event Grid for many subscribers reacting to a change.

Key Vault secrets vs App Configuration settings

Candidates reach for Key Vault to store ordinary configuration that App Configuration was built to hold.

  • Key Vault is scoped to secrets; App Configuration is the intended home for non-secret, centralised settings.
  • Ask whether the described value is confidential before choosing Key Vault over App Configuration.

OpenTelemetry traces vs KQL log queries

Candidates pick a trace-based answer for an aggregate question, or the reverse.

  • Tracing follows a single request end to end; a KQL query answers aggregate questions across many requests at once.
  • Match "where did this one request fail" to tracing, and "what's the error rate" to a KQL query.

6-week study plan

Suggested AI-200 study plan

Move from AI compute and vector storage to integration, security and operations. Adjust this six-week route to your Azure development experience.

  1. AI compute

    • Compare Functions, Container Apps and AKS GPU pools.
    • Manage container images in ACR.
    • Review autoscaling and cold-start mitigation.

  2. Vectors and storage

    • Compare Cosmos DB, Azure SQL and Azure AI Search vector options.
    • Distinguish vector search from hybrid search.
    • Practise embedding generation and chunking.

  3. Pipelines and integration

    • Compare Data Factory, Synapse pipelines, Logic Apps and Power Automate.
    • Use event-triggered Azure Functions.
    • Design retry and idempotency patterns.

  4. Security and identity

    • Use managed identities, app registrations and Foundry RBAC.
    • Review Private Link, customer-managed keys and Key Vault.
    • Configure content filters.

  5. Monitoring and optimisation

    • Trace AI calls with Application Insights and custom telemetry.
    • Monitor tokens, latency and cost.
    • Compare caching, batching and capacity-planning choices.

  6. Review and rehearse

    • Use Focus Weak Spots to revisit weaker topics.
    • Complete two timed, 100-minute Exam Simulator sessions.
    • Review mistakes and repeat difficult scenarios.

Frequently asked

AI-200 FAQs

How much does the AI-200 exam cost?

The AI-200 voucher is USD $165 in the United States, around £128 in the UK; regional pricing varies. Watch for free-voucher promotions around Microsoft Build or Microsoft Ignite. Renewal is free, but it's an annual Associate certification, so factor that into long-term cost planning.

Does the AI-200 certification expire?

Yes. Microsoft Associate certifications including AI-200 expire annually. Renewal is a free, 25–30 question assessment on Microsoft Learn, available in the six-month window before expiry. Fundamentals certifications like AZ-900 don't expire.

What is the AI-200 retake policy if I fail?

Waiting times step up after each fail, and every attempt needs a fresh voucher.

  • First retake: after 24 hours.
  • Second and third retakes: a 14-day wait each.
  • Cap: five attempts per rolling 12 months.
How long should I study for AI-200?

Allow four to eight weeks of focused study if you already develop on Azure. Spend longer if Python, Azure SDKs, containerized applications, Cosmos DB or PostgreSQL vector search, messaging, or KQL-based troubleshooting are new to you. Azure Mastery's readiness gauge helps you decide when to schedule the exam.

What prior experience does AI-200 assume?

AI-200 assumes you already work across the AI-solution lifecycle on Azure — implementation, deployment, security, monitoring — with practical Python, SDK, and container experience. It expects you to already know your way around Azure data services, not learn them from the guide alone. Budget extra time if containers or vector databases are new.

AI-200 vs AI-103 — different roles?

Different emphases. AI-200 validates back-end Azure development for AI solutions, including containers, data services, messaging, security, monitoring, and troubleshooting. AI-103 focuses on developing AI apps and agents with Python and Microsoft Foundry. AI-200 is cloud-platform and service integration; AI-103 is model, agent, retrieval, and AI-application implementation.

AI-200 vs AI-300 — which next?

AI-200 first. It's the AI Cloud Developer cert, building the platform AI workloads run on. AI-300 is the ML Operations Engineer cert, running ML and generative-AI systems in production. AI-200 sits upstream of AI-300 in most roles.
