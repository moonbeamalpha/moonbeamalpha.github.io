How to pass AI-200: Azure AI Cloud Developer

A practical six-week route through containerised hosting, vector-capable data services, messaging, and observability for back-end Azure AI development — plus the data-service trade-offs that catch experienced developers off guard.

Updated 4 September 2026 · ~9 min read

The exam

What is AI-200, and is it for you?

AI-200 earns the Microsoft Certified: AI Cloud Developer Associate credential. It targets developers who contribute to every phase of building AI solutions on Azure, with the emphasis squarely on back-end services and components — requirements, design, development, deployment, security, monitoring, and troubleshooting, rather than the model or agent layer itself.

You should already be comfortable with Python and Azure SDKs, Azure data management services, messaging and eventing, containerised applications, and vector databases before you sit AI-200. It is the back-end development counterpart to AI-103: where AI-103 tests building the AI application itself — models, agents, retrieval — AI-200 tests the platform underneath it, from container hosting to Request Unit tuning to distributed tracing.

AI-200 became generally available on 1 July 2026, so it is still a young credential. Its May 2026 objective update consolidated what used to be a split app, security, and monitoring outline into four cleaner domains, and made pgvector on Azure Database for PostgreSQL and vector indexing on Azure Managed Redis explicit objectives for the first time. The skills measured were last confirmed on 5 May 2026, so anchor your study to that live outline.

Format & domains

Exam format and skills domains

AI-200 mixes question styles: single-answer and multi-select items, ordering tasks around a deployment or troubleshooting workflow, and case studies that group several questions around one back-end architecture scenario.

  • QuestionsRoughly 40–60
  • Duration100 minutes (120-minute seat)
  • Pass score700 / 1000 (scaled)
  • DeliveryOnline or a test centre
  • ValidityRenew free every year
  • FeeVaries by country

Six-week study plan

A realistic six-week study plan

Use the six-week plan below as a starting point if you already build backend Azure services against SDKs professionally; extend it when Cosmos DB, pgvector, or containerised AKS deployment are new to you. It gives the largest domain — data management services — two full weeks, with the remaining three domains taking one week each.

  1. Develop containerized solutions on Azure

    Container hosting: build, store, version, and manage images with Azure Container Registry and ACR Tasks, then deploy containers to Azure App Service, including environment variables and secrets. Container orchestration: deploying to Azure Container Apps with environment and revision management, event-driven scaling with KEDA, deploying to AKS by manifest, and monitoring and troubleshooting logs, events, and connectivity on both platforms.

  2. AI data solutions with Azure Cosmos DB for NoSQL

    Connect to Cosmos DB for NoSQL with the SDK and run queries, optimise Request Unit consumption and query performance through indexing policies and consistency levels, store and retrieve embeddings for vector similarity search, and implement a change feed processor to react to new or updated items.

  3. AI data solutions with PostgreSQL and Azure Managed Redis

    Connect and query Azure Database for PostgreSQL by SDK, model schemas and indexing strategies, tune pgvector compute overhead, configure resources for vector workloads, and implement retrieval-augmented generation patterns with metadata filters. Then Azure Managed Redis: caching, expiration, invalidation, and vector indexing for similarity search.

  4. Connect to and consume Azure services

    Event- and message-based solutions: Azure Service Bus with dead-letter queue handling, topics, and subscriptions, and Azure Event Grid with filters, custom events, and retries. Then Azure Functions: building serverless APIs with triggers and bindings, and configuring and deploying function apps.

  5. Secure, monitor, and troubleshoot Azure solutions

    Secure secrets with Azure Key Vault, including rotation and retrieval, and store app configuration with Azure App Configuration. Then observability: tracing distributed systems with OpenTelemetry SDKs and writing KQL queries to analyse logs and metrics.

  6. Review and exam simulation

    Revisit the data-service decision the exam leans on hardest: which vector store fits which consistency, latency, and cost profile. Then switch to sharpening: drill your weakest domain daily and sit two full-length timed practice runs. Book the exam once your readiness sits comfortably above the pass mark.

Focus areas

The hardest AI-200 topics

AI-200 rewards specific configuration knowledge over general familiarity, so give these five areas focused practice.

Choosing the right vector store for the workload

Cosmos DB for NoSQL, Azure Database for PostgreSQL with pgvector, and Azure Managed Redis all support vector similarity search, and the exam expects you to match consistency requirements, latency budget, and relational needs to the right service rather than defaulting to whichever you know best.

Tuning under load, not just scaling up

Cosmos DB questions expect specific indexing-policy and consistency-level choices to control Request Unit cost, and PostgreSQL questions expect connection-optimisation and compute-sizing decisions to control latency and pgvector overhead. "Scale up the tier" is rarely the answer the exam is looking for.

Container hosting vs container orchestration

Deploying a container to Azure App Service, running it on Azure Container Apps with KEDA-driven scaling, and deploying manifests to full AKS solve overlapping problems at different levels of control and complexity. Match the requirement's scaling and orchestration needs to the lightest option that satisfies them.

Service Bus vs Event Grid for a given integration

Service Bus suits ordered, transactional, dead-letter-aware messaging between known producers and consumers. Event Grid suits fan-out, filtered, retryable event delivery to many subscribers. The exam names a specific integration requirement and expects the messaging pattern that fits it, not just "a queue".

Observability with real instrumentation detail

AI-200 tests actual OpenTelemetry SDK instrumentation and KQL query-writing rather than "turn on Application Insights". Expect a scenario describing a specific tracing gap or a log query requirement and asking you to write or fix the instrumentation, not just recognise the monitoring tool.

How to practise

Practise the way the exam works

Reading service documentation builds recognition of feature names, but AI-200 tests specific configuration choices under a stated constraint, which is a different skill. Retrieval practice closes that gap: read a scenario, decide on the indexing policy, connection setting, or messaging pattern before you check the explanation, since pulling the answer out of your own head is what fixes the many "which data service" and "which messaging pattern" decisions the exam is built on.

Pair that with hands-on repetition: stand up a small Cosmos DB container with a vector index, connect Azure Database for PostgreSQL with pgvector, and wire a Container App to a Service Bus queue. Reading a configuration option becomes far faster to recognise once you have set a similar one up yourself. Finish with at least two full-length, mixed-domain simulator runs before you book, and review every wrong answer rather than just the score.

Exam day

Tactics for exam day

If you are sitting online, run the system check the day before and clear your desk, since proctors will ask you to show the room and remove anything within reach. Arrive early either way, because a rushed start eats into your focus during the configuration-heavy scenario questions.

With 100 minutes for 40 to 60 questions you have roughly a minute and a half to two minutes each, which is comfortable if you keep moving. Use the mark-for-review flag on anything that makes you pause and return to it once you have banked the easy marks. Read every data-service and messaging question twice: the trap is usually a single consistency level, indexing choice, or delivery guarantee, and a slower second read pays off.

Case studies bundle several questions around one back-end architecture scenario, and once you move past a case you generally cannot return to it, so answer everything inside a case fully before advancing. Remember the score is scaled: you need 700 out of 1000, not a perfect run, so an unfamiliar configuration is not a disaster. Flag it, make your best call, and keep your momentum.

Frequently asked

AI-200 FAQs

How hard is the AI-200 exam?

AI-200 is a back-end engineering exam more than an AI-concepts exam: it assumes working Python or SDK experience and asks specific questions about indexing policies, connection pooling, and messaging patterns rather than definitions. If Cosmos DB, pgvector, or Azure Managed Redis are new to you, budget extra hands-on time for the vector-workload tuning detail.

How long should I study for AI-200?

The six-week plan on this page is a practical starting point if you already write backend Azure services against SDKs professionally. Extend it when Cosmos DB, Azure Database for PostgreSQL with pgvector, or containerised deployment on AKS or Container Apps are new territory, since the exam rewards specific configuration knowledge over general familiarity. Use your domain-level practice results to decide when to add or repeat a week.

Do I need AI-901 before AI-200?

AI-901 is not a formal prerequisite, but Microsoft's own certification path lists it as the current fundamentals route into AI-200. If AI concepts and vector search are new to you at a conceptual level, sitting AI-901 first gives you vocabulary the associate exam assumes. If you already build backend Azure services and are comfortable with vector data, you can go straight to AI-200.

Is AI-200 the same as AI-103?

No. AI-200 validates back-end Azure engineering for AI solutions: containers, vector-capable data services, messaging, and observability. AI-103 validates building the AI application layer itself — deploying models, building agents, and implementing retrieval-augmented generation against Microsoft Foundry. AI-200 is the platform and integration layer beneath an AI application; AI-103 is the application and agent layer on top of it. Many engineers eventually need both.

What is the passing score for AI-200, and does it expire?

You need 700 out of 1000 to pass, on a scaled score rather than a raw percentage, so it does not map to a fixed number of correct answers. Like other Microsoft Associate certifications, AI-200 also expires annually, with a free online renewal assessment on Microsoft Learn that opens in the six-month window before your expiration date.

How much does AI-200 cost and can I retake it if I fail?

Exam pricing varies by country, so check Microsoft's certification page for the fee where you live rather than trusting a figure you read elsewhere. If you do not pass, the first retake is allowed after 24 hours, the second and third each require a 14-day wait, and Microsoft caps retakes at five attempts per rolling 12-month period. Each attempt needs a new booking.
