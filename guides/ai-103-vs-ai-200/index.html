AI-103 vs AI-200: AI apps and agents, or AI cloud developer?

Two 2026 Azure AI Associate exams that sit side by side rather than in sequence. See which layer of the AI stack each one certifies.

Updated 4 September 2026 · ~9 min read

Quick answer

AI-103 or AI-200: the short version

These are not a beginner-and-advanced pair. They are two parallel Associate specialisations that split the AI stack in half, and the right one depends on which half you actually own.

Choose AI-103 if you build the AI itself

AI-103 (Microsoft Certified: Azure AI Apps and Agents Developer Associate) is the right exam if your job is choosing and deploying models in Microsoft Foundry, building generative and agentic applications, implementing retrieval-augmented generation, and shipping computer vision, text analysis, or information-extraction solutions. It expects working Python and hands-on familiarity with Foundry SDKs.

Choose AI-200 if you build the cloud back end underneath it

AI-200 (Microsoft Certified: AI Cloud Developer Associate) is the right exam if your job is containerised hosting for AI workloads, wiring vector-capable data services such as Cosmos DB, Azure Database for PostgreSQL, and Azure Managed Redis, connecting services through Service Bus, Event Grid, and Azure Functions, and securing and monitoring the resulting system. It expects Azure SDK fluency and infrastructure judgement more than model-behaviour judgement.

Neither is a prerequisite for the other. See "Is one a prerequisite for the other?" below for how the two fit together on a full-stack AI team.

What AI-103 actually tests

What AI-103 actually tests

AI-103 spreads across five domains, but generative AI and agentic solutions carries the most weight, and the exam expects you to reason about model and agent behaviour, not just recall Foundry terminology.

AI-103 skills measured (outline effective 16 April 2026)
DomainWeight
Plan & manage an Azure AI solution25–30%
Implement generative AI & agentic solutions30–35%
Implement computer vision solutions10–15%
Implement text analysis solutions10–15%
Implement information extraction solutions10–15%

Planning covers choosing the right Foundry service and model family for a task, designing infrastructure and deployment options, monitoring quotas and drift, and applying responsible AI guardrails and audit trails. The generative and agentic domain covers building applications with LLMs and multimodal models, implementing retrieval-augmented generation, and building agents with tool integration, orchestrated multi-agent workflows, and observability through tracing and token analytics. The three smaller domains round out the practical surface: image and video generation with responsible-AI content filters, language-model text analysis and speech workflows, and retrieval pipelines that combine semantic, hybrid, and vector search with document extraction through Content Understanding.

What AI-200 actually tests

What AI-200 actually tests

AI-200 has no domain about models, prompts, or agents at all. It is a backend Azure developer exam that happens to be scoped to the services AI workloads lean on hardest: containers, vector-capable data stores, and event-driven integration.

AI-200 skills measured (outline effective 5 May 2026)
DomainWeight
Develop containerised solutions on Azure20–25%
Develop AI solutions using Azure data services25–30%
Connect to & consume Azure services20–25%
Secure, monitor & troubleshoot Azure solutions20–25%

Containerised solutions covers building and versioning images with Azure Container Registry, deploying to Azure Container Apps with event-driven scaling through KEDA, and running manifests on Azure Kubernetes Service. The largest domain, AI data services, is where AI-200 earns its name: connecting to Azure Cosmos DB for NoSQL and running vector similarity search, modelling schemas and running pgvector workloads in Azure Database for PostgreSQL, and implementing caching and vector indexing in Azure Managed Redis. Connect and consume covers Service Bus, Event Grid, and Azure Functions, and the final domain covers Key Vault, App Configuration, OpenTelemetry tracing, and writing KQL queries to diagnose a solution once it's live.

Prerequisite question

Is one a prerequisite for the other?

No. AI-103 and AI-200 are both standalone Associate exams, and Microsoft does not require either as a prerequisite for the other. Each optionally follows AI-901 (Azure AI Fundamentals) as a conceptual lead-in, but AI-103 and AI-200 do not lead into each other — they run in parallel as two different specialisations within the same broad Azure AI field.

That parallel structure is deliberate. AI-103 assumes the Foundry project, the deployed model, and the underlying data store already exist, and tests what you build with them. AI-200 assumes none of that is your concern and tests whether you can stand the infrastructure up, connect it, secure it, and keep it running. A team building a production AI product typically needs both skill sets, but rarely from the same person on day one.

If you're deciding which to sit first with no strong pull either way, pick based on which domain list reads as more familiar right now: AI-103 if Foundry SDKs, prompts, and RAG pipelines already feel comfortable; AI-200 if Cosmos DB, Container Apps, and Service Bus already feel comfortable. There is no efficiency gained from sitting one before the other, since the domain content barely overlaps.

Career value

How each certification helps your career

AI-103 is the credential to point to for "AI engineer", "AI application developer", or "AI agent developer" roles — anywhere the job is choosing models, designing agent behaviour, and shipping generative features. It demonstrates you can evaluate a model or an agent for fabrication, relevance, and safety, not just wire an API call.

AI-200 is the credential for "AI cloud developer" or "backend engineer for AI systems" roles, where the job is making sure the vector database, the containerised inference service, and the message queue behind an AI product actually hold up under load. It's also this site's suggested next step for anyone whose AZ-204 (Azure Developer Associate) credential is ageing out, since AZ-204 retired on 31 July 2026 and AI-200's compute, data, and integration domains cover the closest current match to that back-end developer skill set.

Neither certification guarantees a role or a pay rise on its own. What both reliably provide is a Microsoft-set bar you can point to when a job description or a promotion case asks for AI-specific skills, rather than a general software-engineering credential that predates the AI era.

Take both?

Should you take both AI-103 and AI-200?

For engineers on a full-stack AI platform team — the kind of team responsible for a product end to end, from the agent's behaviour down to the database it queries — both certifications map cleanly onto real, distinct parts of the job. Together they cover the AI application layer and the cloud infrastructure layer with almost no gap between them.

For a specialist who only ever works one side of that line, taking both offers limited extra signal. A model- and agent-focused engineer gets little from AI-200's container and messaging domains, and a backend-infrastructure engineer gets little from AI-103's prompt-engineering and vision domains. In those cases, sit the one that matches your role and revisit the other only if your responsibilities expand.

If you do plan to sit both, there is no real efficiency in sequencing them tightly together, since the domain overlap is minimal — treat them as two separate study projects rather than one combined plan. The AI-103 study guide and the AI-200 study guide each lay out their own six-week plan.

Frequently asked

AI-103 vs AI-200 FAQs

Is AI-200 a prerequisite for AI-103, or the other way round?

No. Neither exam requires the other, and Microsoft's certification paths list them as parallel Associate specialisations rather than a sequence. AI-901 (Azure AI Fundamentals) is an optional conceptual lead-in for both, but AI-103 and AI-200 themselves sit side by side, not one after the other.

What's the real difference between AI-103 and AI-200?

AI-103 certifies the AI application and agent layer: choosing and deploying models in Microsoft Foundry, building retrieval-augmented and agentic workflows, and implementing vision, text, and extraction pipelines. AI-200 certifies the cloud infrastructure those solutions run on: containerised hosting, vector-capable data services such as Cosmos DB and PostgreSQL, event-driven messaging, Azure Functions, and securing and monitoring the whole thing. One is model- and agent-facing; the other is back-end and infrastructure-facing.

Which one should I take if I'm building a chatbot or an AI agent?

AI-103. Its Implement Generative AI and Agentic Solutions domain, worth 30 to 35%, covers exactly this: building agents with Microsoft Foundry, defining tool schemas and conversation memory, and orchestrating multi-agent workflows. AI-200 does not test conversational or agentic design at all.

Which one should I take if I own the data and messaging layer underneath an AI solution?

AI-200. Its two largest domains cover exactly that: developing AI solutions with Azure Cosmos DB, Azure Database for PostgreSQL, and Azure Managed Redis for vector storage, and connecting services with Azure Service Bus, Event Grid, and Azure Functions. AI-103 assumes those services exist and focuses on what the application does with them, not how they are built or secured.

Do AI-103 and AI-200 expire the same way?

Yes. Both are Microsoft Associate certifications and both require annual renewal, free, through a short online assessment on Microsoft Learn during the six-month window before expiry. Passing one does not affect the other's renewal clock.

Can I take both, and does one make the other easier?

Yes, and it's a common pairing for anyone on a full-stack AI platform team. The two domain lists barely overlap, so passing one does not meaningfully shorten study time for the other, but both assume comparable Python fluency and familiarity with Azure identity and monitoring, so that groundwork only needs building once.
