The exam

What is the AZ-400 exam?

AZ-400 is the expert-level exam for the Microsoft Certified: DevOps Engineer Expert credential — Microsoft's senior DevOps certification spanning both Azure DevOps and GitHub. Azure Developer Associate retired on 31 July 2026; an Azure Developer Associate credential earned before that date still satisfies the AZ-400 prerequisite, but new candidates now reach it through AZ-104 (Azure Administrator Associate) instead.

AZ-400 is the broadest exam in the Azure family by service surface — you'll be tested across five DevOps domains, with the build/release pipelines domain alone weighted at 50–55% of the exam. Expect dual coverage throughout:

  • Azure Pipelines and GitHub Actions
  • Azure DevOps Repos and GitHub repositories
  • Bicep and ARM templates
  • Security scanning — Microsoft Defender for DevOps, GitHub Advanced Security, Dependabot, CodeQL
  • Monitoring — Azure Monitor, Application Insights, KQL queries
  • Progressive deployment patterns — blue-green, canary, ring, feature flags via Azure App Configuration

Microsoft updated the AZ-400 skills outline on 27 July 2026 with minor updates across all five domains — branching strategies, package management, deployments, IaC, auth/secrets, and monitoring. Common traps

Where AZ-400 candidates slip

Four recurring misconceptions that trip up otherwise well-prepared AZ-400 candidates, grounded in the current skills outline.

The pipelines domain has two ecosystems, and a question won't tell you which one

AZ-400 treats Azure Pipelines and GitHub Actions as equally examinable, not one as the real answer and the other a footnote.

  • The exam is testing your working fluency across both ecosystems, whichever one is your day job's tool.
  • Practise reading unfamiliar YAML in whichever pipeline platform you use less at work.

Managed identities and service principals solve the same problem for different lifetimes

A managed identity dies with the resource it's attached to, while a service principal can outlive any single resource.

  • The exam is testing whether you caught the lifetime constraint behind the named authentication mechanism.
  • Ask whether the identity needs to outlive one resource before choosing between the two options.

Blue-green, canary, and ring deployments are not synonyms for gradual rollout

Blue-green swaps all traffic at once, canary exposes a small percentage first, and ring moves through defined cohorts in sequence.

  • A rollback or blast-radius constraint points to exactly one deployment pattern, and spotting it is the scored step.
  • Define each pattern by its rollback behaviour, the specific trait that separates all three.

A quality gate and a release gate check different things at different times

A quality gate checks the build artefact inside the pipeline, while a release gate checks external conditions between stages.

  • Placing an approval check as a release gate rather than a quality gate is exactly what's being checked.
  • Match each gate to when it runs, inside a stage or between two stages, before answering.

10-week study plan

Suggested AZ-400 study plan

Follow this suggested ten-week route, adjusting the pace to your experience. Build from team workflows and Git to pipelines, deployment, security and monitoring. Finish with focused review and timed practice.

  1. Process and communication

    • Plan work with Azure Boards, dashboards and GitHub Flow.
    • Track cycle time, lead time and recovery time.
    • Connect team documentation, wikis, webhooks and Teams.

  2. Source control

    • Compare trunk-based, feature and release branches.
    • Practise pull requests and branch protection rules.
    • Manage large repositories, recover Git data and clean history.

  3. Packages and dependencies

    • Publish packages with GitHub Packages and Azure Artifacts.
    • Manage feeds, dependencies and artifact versions.
    • Compare SemVer and CalVer; configure quality and release gates.

  4. Build pipelines

    • Write YAML for Azure Pipelines and GitHub Actions.
    • Choose agents and runners; configure triggers and stages.
    • Reuse templates and add environment checks and approvals.

  5. Automated testing

    • Compare unit, integration and load tests.
    • Configure test tasks, agents and results integration.
    • Use code coverage to identify gaps.

  6. Deployment strategies

    • Compare blue-green, canary, ring and progressive releases.
    • Use feature flags, A/B testing, slots and hotfix paths.
    • Practise container and database deployments.

  7. Infrastructure and maintenance

    • Deploy with Bicep, ARM templates and Azure Deployment Environments.
    • Review Azure Automation State Configuration and Azure Machine Configuration.
    • Monitor pipeline health, optimise cost and speed, set retention and migrate to YAML.

  8. Security and compliance

    • Configure identities, tokens, service connections and permissions.
    • Protect secrets with Key Vault, secure files and workload identity federation.
    • Review Defender for DevOps, GitHub Advanced Security, Dependabot, CodeQL and container scans.

  9. Monitoring and instrumentation

    • Connect Azure Monitor, Logs and Application Insights to DevOps tools.
    • Review resource Insights, GitHub Insights and pipeline alerts.
    • Practise metrics analysis, distributed tracing and basic KQL.

  10. Review and rehearse

    • Revisit weaker topics with Focus Weak Spots and decay alerts.
    • Complete two timed, 100-minute Exam Simulator sessions.
    • Review mistakes and use practice results to guide further study.

Frequently asked

AZ-400 FAQs

Which exam do I need to have passed before AZ-400?

Azure Developer Associate (AZ-204) retired on 31 July 2026. An Azure Developer Associate credential earned before that date still satisfies the AZ-400 prerequisite, but new candidates now reach it through Azure Administrator Associate (AZ-104) instead.

What's the going rate for an AZ-400 exam attempt?

The AZ-400 voucher is USD $165 in the US, or around £128 in the UK — pricing varies by region. Microsoft sometimes runs free-voucher promotions around Build or Ignite. The DevOps Engineer Expert tier also needs annual renewal, free and online, once earned.

Will my DevOps Engineer Expert badge lapse if I don't renew?

Yes. Expert certifications including DevOps Engineer Expert expire annually. Renewal is a free, short online assessment on Microsoft Learn within six months of your expiry date, targeting recent outline updates.

If I fail AZ-400, how long before I can retake it?

Not immediately, and each attempt needs its own voucher.

  • First retake: after 24 hours.
  • Second and third retakes: a 14-day wait each.
  • Cap: five attempts per rolling 12 months.
What's a realistic AZ-400 study timeline?

Plan eight to twelve weeks, even if you already hold AZ-104 or AZ-204. AZ-400 covers an enormous surface: both pipeline ecosystems, both repository platforms, Bicep and ARM, plus security scanning and monitoring. Don't book until the readiness gauge shows around 730 or higher.

AZ-400 vs AZ-305 — which Expert cert should I take?

Pick the one that matches your role. AZ-400 is for SREs, platform engineers, and developers who own CI/CD; AZ-305 is for architects designing the systems those pipelines deploy. Both use Azure Administrator Associate as a prerequisite, and they're complementary rather than competing.

Does AZ-400 really test both Azure DevOps and GitHub equally?

Yes, and it's the exam's defining feature. AZ-400 treats Azure Pipelines and GitHub Actions as parallel tracks, expecting familiarity with both ecosystems throughout. Candidates who've only worked in one typically need dedicated study time in the other before they're exam-ready.

What does the AZ-400 exam format actually look like?

AZ-400 follows Microsoft's general 40–60 question format, with the mix varying by sitting. Azure Mastery's bank weights single-answer and scenario-based items heaviest, with multi-select, drag-and-drop, and linked case-study questions filling out the rest — all original practice content.
