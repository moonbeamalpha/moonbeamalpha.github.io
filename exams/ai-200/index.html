The exam

What is the AI-200 exam?

AI-200 is the Microsoft Certified: AI Cloud Developer Associate exam — the credential hiring managers expect when posting "AI Cloud Developer", "AI Platform Engineer", or "Vector Database Developer" roles. AI-200 covers building AI-powered cloud solutions on Azure: compute, vector storage, integration pipelines, security and identity for AI workloads, and operational monitoring.

AI-200 is hands-on and infrastructure-aware. It validates that you can develop AI-powered compute solutions (Azure Functions, Container Apps, AKS for AI workloads), develop for vector-enabled storage and data (Azure Cosmos DB vector search, Azure SQL vector capabilities, Azure AI Search vector indexes), implement AI pipelines and integration (Azure Data Factory, Logic Apps, event-driven patterns), implement security and identity for AI (managed identities, Microsoft Entra, Private Link, content filters), and monitor and optimise AI solutions (Application Insights, cost controls, performance tuning). Expect scenario questions that combine compute, data, and identity choices.

Microsoft updated the AI-200 skills outline on 5 May 2026, consolidating the previous five-domain structure into four. Every question in Azure Mastery's AI-200 bank is mapped to the current outline — no leftover questions on retired services. Read the official outline at learn.microsoft.com.

AI-200 exam objectives

Four domains, with weights set by Microsoft's 5 May 2026 update. Every domain summary below is paraphrased from the official skills outline; Azure Mastery tags each question to its assessed domain so you can see where your weak spots cluster.

Develop containerized solutions on AzurePublished weight 20–25%

55 exam-scoped practice questions in the app

Explore Compute topics
  • Implement container application hosting
  • Implement container-orchestrated solutions

This domain is about hosting the compute layer AI workloads run on, not writing the AI logic itself. Container application hosting covers building and versioning images with Azure Container Registry, running Registry Tasks, and deploying containers to App Service with the right environment variables and secrets wired in. Container-orchestrated solutions moves up a level: Container Apps environment configuration and revision management, event-driven scaling with KEDA, deploying to AKS from manifest files, and — critically — troubleshooting a live deployment by reading logs, events, and end-to-end connectivity rather than just standing one up and walking away.

Develop AI solutions by using Azure data management servicesPublished weight 25–30%

62 exam-scoped practice questions in the app

Explore Data topics
  • Develop AI solutions by using Azure Cosmos DB for NoSQL
  • Develop AI solutions by using Azure Database for PostgreSQL
  • Integrate Azure Managed Redis in AI solutions

The exam's largest domain, and the most AI-specific. Cosmos DB for NoSQL objectives go beyond basic querying — indexing policies and consistency levels for Request Unit efficiency, storing and searching vector embeddings, and change feed processors for reacting to new or updated items. PostgreSQL adds schema and indexing design, pgvector-aware performance tuning, connection optimisation, and running retrieval-augmented generation patterns with metadata filters. Managed Redis is smaller but distinct: caching with expiration and invalidation, plus vector indexing for its own similarity search. Treating these three services as interchangeable "vector databases" is the fastest way to lose marks here.

Connect to and consume Azure servicesPublished weight 20–25%

55 exam-scoped practice questions in the app

Explore Integration topics
  • Develop event- and message-based AI solutions
  • Develop and implement Azure Functions

Two skill groups, and both are about moving data and triggering work reliably rather than processing it. Event- and message-based solutions cover Azure Service Bus (dead-letter queues, topics, subscriptions) and Event Grid (filters, custom events, retries) — the exam expects you to know which one fits a given reliability or fan-out requirement. Azure Functions rounds the domain out: building serverless APIs with the right triggers and bindings, then configuring and deploying the function app itself. Expect scenarios that ask you to choose between queued and event-driven patterns for a described AI workload, not just define each service.

Secure, monitor, and troubleshoot Azure solutionsPublished weight 20–25%

48 exam-scoped practice questions in the app

Explore Operations topics
  • Implement secure Azure solutions
  • Monitor and troubleshoot Azure solutions

The domain most candidates underestimate, because it splits between security and observability rather than AI itself. Secure solutions means Key Vault secret rotation and retrieval plus Azure App Configuration for externalised settings — knowing which store fits secrets versus non-secret config. Monitoring and troubleshooting is where distributed AI pipelines actually get debugged: OpenTelemetry SDK tracing across services, and writing KQL queries against Azure Monitor logs and metrics to find where a request failed or slowed down. Questions here tend to hand you a symptom and ask which telemetry source or query surfaces the cause.

Common traps

Where AI-200 candidates slip

Five recurring misconceptions that trip up otherwise well-prepared AI-200 candidates, grounded in the current skills outline.

Studying the old five-domain outline

AI-200's skills outline was consolidated on 5 May 2026 from a five-domain structure into four. Azure OpenAI, Microsoft Foundry, Azure AI Search, and general AI telemetry can still appear as supporting context inside a scenario, but they are no longer top-level objective headings — Container Apps, Cosmos DB, PostgreSQL, and Managed Redis carry more of the published weight than candidates studying an outdated outline expect.

Treating every vector store the same way

All three services in "Develop AI solutions by using Azure data management services" can run vector similarity search, but each has its own configuration surface — Cosmos DB's indexing policies and consistency levels, PostgreSQL's pgvector compute overhead and connection optimisation, Managed Redis's own vector-indexing setup. A scenario naming a specific service is testing that service's tuning knobs, not generic "vector database" knowledge.

Service Bus vs Event Grid — reliability vs reaction

Service Bus is built for reliable, ordered message delivery with dead-letter handling when a consumer can't process a message; Event Grid is built for reacting to discrete events with filtering and automatic retries, not guaranteed ordered processing. A scenario asking for guaranteed delivery to a specific back-end queue wants Service Bus; one asking for many subscribers reacting to a state change wants Event Grid.

Key Vault secrets vs App Configuration settings

Azure Key Vault is for secrets — connection strings, API keys, certificates — with rotation and access-policy control built around confidentiality. Azure App Configuration is for everything else an app needs to look up centrally: feature flags and non-secret, environment-specific values. Reaching for Key Vault to store ordinary configuration is a common miss the exam is written to catch.

OpenTelemetry traces vs KQL log queries

Distributed tracing with OpenTelemetry shows the path a single request took across services and where time was spent; KQL queries against Azure Monitor answer aggregate questions across many requests — error rates, patterns over time, correlated failures. Troubleshooting scenarios usually need one specifically, and picking a trace-based answer for an aggregate question, or the reverse, is a frequent operations-domain slip.

Most candidates pass AI-200 after four to eight weeks of focused study, depending on prior Azure experience.     • Week 5: Monitor and optimize AI solutions — Application Insights for AI calls, custom telemetry for tokens and latency, distributed tracing, cost dashboards, caching and batching strategies, capacity planning.

Frequently asked

AI-200 FAQs

How much does the AI-200 exam cost?

The AI-200 voucher is USD $165 in the United States. Pricing varies by region — in the UK it's typically around £128. Microsoft sometimes runs free-voucher promotions during events such as Microsoft Build or Microsoft Ignite, so check your Microsoft Learn profile for any active offers before booking. AI-200 also requires annual renewal (free, online), so factor that into long-term cost planning.

Does the AI-200 certification expire?

Yes. Microsoft Associate certifications including AI-200 expire annually. Renewal is free — a 25–30 question online assessment on Microsoft Learn within the six-month window before your expiration date. The renewal targets recent skills outline updates, so staying current is straightforward if you remain broadly active in the role. (Fundamentals certifications such as AZ-900 are different — those don't expire.)

What is the AI-200 retake policy if I fail?

The first retake is allowed after 24 hours. Second and third retakes each require a 14-day wait. Microsoft caps retakes at five attempts per 12-month rolling period. Each attempt requires a new voucher purchase.

How long should I study for AI-200?

Allow four to eight weeks of focused study if you already develop on Azure. Spend longer if Python, Azure SDKs, containerized applications, Cosmos DB or PostgreSQL vector search, messaging, or KQL-based troubleshooting are new to you. Azure Mastery's readiness gauge helps you decide when to schedule the exam.

What prior experience does AI-200 assume?

AI-200 assumes you already work across the full AI-solution lifecycle on Azure — implementation, deployment, security, monitoring, and troubleshooting — with practical comfort in Azure and third-party SDKs, containerized applications, and Python. It expects you to already know your way around Azure data management services and messaging, not to learn them from the study guide alone. If containers or vector-capable databases are genuinely new to you, budget extra time beyond the usual four-to-eight-week window.

AI-200 vs AI-103 — different roles?

Different emphases. AI-200 validates back-end Azure development for AI solutions, including containers, data services, messaging, security, monitoring, and troubleshooting. AI-103 focuses on developing AI apps and agents with Python and Microsoft Foundry. AI-200 is cloud-platform and service integration; AI-103 is model, agent, retrieval, and AI-application implementation.

AI-200 vs AI-300 — which next?

AI-200 first. AI-200 is the AI Cloud Developer Associate cert — building the platform that AI workloads run on. AI-300 is the ML Operations Engineer Associate cert — running and operating ML and generative-AI systems in production (MLOps and GenAIOps). AI-200 is upstream of AI-300 in most roles. Take AI-200 to build the platform, AI-300 to operate models and pipelines on top of it.
